Modern infrastructure runs on software. Everyday activities—banking, retail, travel reservations, patient records, and transit networks—rely on interconnected codebases.

When you book a flight online, submitting a form triggers communication across dozens of independent services:
- Identity verification and passport validation.
- Visa clearance checks.
- Seat-inventory reservations.
- Frequent-flyer account updates.
- Aircraft fuel load calculations.

Software developers design and maintain these pipelines. Building reliable systems requires understanding both programming fundamentals and the specific rules of a domain. For instance, calculating statutory taxes or handling date boundaries requires precise logical conditions.

## Silent Infrastructure

Most users only notice software when it fails. In 1969, [Margaret Hamilton](https://en.wikipedia.org/wiki/Margaret_Hamilton_(scientist)) led the MIT team that developed the Apollo on-board flight software. Her architecture prioritized critical radar tasks during landing, preventing an abort when radar sensors overloaded the Apollo 11 computer.

![Margaret Hamilton with Apollo guidance source code](./margeret-action.jpg)

Software development is practical craftsmanship. Today, meteorologists, physicists, biologists, and financial analysts write code to model data and automate decisions.

## Looking Ahead

Computers execute instructions literally. A human understands ambiguous requests from context; a computer requires exact rules. Over Part 1, you learned how to:
- Sequence statements and manage program entry points.
- Print output and parse typed console input.
- Store data in primitive variables and evaluate arithmetic expressions.
- Control program flow using branching logic and boolean conditions.

In Part 2, you will expand this foundation to handle repeating logic with loops and organize code into reusable methods.
