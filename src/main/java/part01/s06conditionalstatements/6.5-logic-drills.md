## The Engineer's Mindset: Dissecting Logic Problems

When you encounter problems like `LeapYear` or `GiftTax`, the difficulty is rarely the Java syntax. The real challenge is **translation**: taking ambiguous human descriptions and converting them into an unambiguous, mutually exclusive set of rules.

Before writing a single line of Java, run through this 3-step discipline:

### 1. Identify Inputs and Boundaries
List every variable and its domain. Ask:
- Can this number be negative?
- Can this number be zero? (Watch out for division by zero with `%` or `/`).
- Are the boundaries inclusive (`>=`, `<=`) or exclusive (`>`, `<`)?

### 2. Map Mutually Exclusive Cases
Draw a small truth table or decision tree. If two conditions can be true at the same time, decide which one takes precedence, or combine them with logical AND (`&&`).

### 3. Test the Edge Values
If a rule triggers at `100`, test three values on paper:
- `99` (just below)
- `100` (on the boundary)
- `101` (just above)

## De Morgan's Laws: Inverting Logic

Often, it is easier to state when something is **invalid** than when it is valid. De Morgan's laws show how negation interacts with `&&` and `||`:

$$\neg(A \land B) \iff \neg A \lor \neg B$$
$$\neg(A \lor B) \iff \neg A \land \neg B$$

In Java terms:
1. `!(A && B)` is equivalent to `!A || !B`
2. `!(A || B)` is equivalent to `!A && !B`

### Practical Example: Range Validation

Suppose a valid score must be between 0 and 100 inclusive:
```java
// Expressed positively:
boolean isValid = score >= 0 && score <= 100;

// Expressed as rejection criteria (its logical opposite):
boolean isInvalid = score < 0 || score > 100;
```
Notice how `>=` flipped to `<`, `<=` flipped to `>`, and `&&` flipped to `||`. Flipping conditions cleanly keeps your code from nesting five levels deep.

## The Waterfall Pattern: Stepped Rates & Brackets

In problems like tax brackets or utility billing, rates apply in "slices" rather than a flat percentage across the entire total.

```
Total Consumption: 250 units
[  0 to 100  ] -> 100 units at Rate 1
[ 101 to 200 ] -> 100 units at Rate 2
[ 201 to 250 ] ->  50 units at Rate 3
```

When calculating stepped amounts:
1. Check from highest bracket to lowest (or vice versa).
2. Calculate the tax or cost for the portion that exceeds the bracket's lower limit.
3. Add the accumulated base cost from all lower tiers.

## Cyclic & Modular Logic

The remainder operator `%` is the clockwork operator. Whenever a problem involves repeating patterns, wraparounds, or cycles:

- Days of the week (0 to 6, repeats every 7)
- 24-hour clock (0 to 23, repeats every 24)
- Turn-taking games (Player 1, Player 2, Player 3)

$$\text{Next Step} = (\text{Current} + \text{Step}) \pmod{\text{CycleLength}}$$
