## 1. Inverting Conditions in Code

An `if` statement often starts with a positive check: it tests that every requirement passes.

```java
int pressurePsi = 38;

// Positive check: safe only if both boundary requirements pass
if (pressurePsi >= 30 && pressurePsi <= 50) {
    System.out.println("Pressure is within safe limits.");
}
```

### Key Terminology Explained

- **Guard Clause:** A conditional check placed at the start of a code block that detects invalid inputs or error conditions early and exits immediately.
- **Condition Inversion:** Rewriting a condition so it tests for the opposite situation (testing for failure rather than success).
- **Short-Circuit Evaluation:** Java's rule of evaluating `&&` and `||` from left to right, stopping as soon as the result is determined.

### The Guard Clause Pattern: Rejection Checks

Programs often handle invalid input first and exit early. This pattern is called a **guard clause**.

To write a rejection check, identify what causes the input to fail:
- Valid: pressure is at least 30 and at most 50.
- Invalid: pressure is less than 30 or greater than 50.

Success requires every requirement to pass (`&&`). Failure occurs if any single requirement fails (`||`).

```java
// Rejection check (guard clause): exit early if anything is invalid
if (pressurePsi < 30 || pressurePsi > 50) {
    System.out.println("Warning: Unsafe pressure detected!");
    return;
}

// If execution reaches here, the pressure is safe
System.out.println("Pressure is within safe limits: " + pressurePsi + " PSI");
```

### De Morgan's Rules for Inverting Code

De Morgan's rules describe how to negate compound conditions systematically.

To negate a condition in code, apply two steps:
1. **Flip every comparison operator to its opposite:**
   - `>=` flips to `<`
   - `<=` flips to `>`
   - `>` flips to `<=`
   - `<` flips to `>=`
   - `==` flips to `!=`
   - `!=` flips to `==`
2. **Swap the logical operator:**
   - `&&` becomes `||`
   - `||` becomes `&&`

In Java terms:
- `!(A && B)` is equivalent to `!A || !B`
- `!(A || B)` is equivalent to `!A && !B`

### Example 1: Validating Username Length

Suppose a web application requires a username to be between 3 and 12 characters long. Here are the two ways to write it:

```java
int length = 8;

// Approach A: Positive check
if (length >= 3 && length <= 12) {
    System.out.println("Username length accepted.");
} else {
    System.out.println("Username must be between 3 and 12 characters.");
}

// Approach B: Guard clause (inverted condition)
if (length < 3 || length > 12) {
    System.out.println("Username must be between 3 and 12 characters.");
    return;
}
System.out.println("Username length accepted.");
```

Here is how both approaches evaluate across different inputs:

| Test Input | Expected Result | Approach A (Positive Check) | Approach B (Guard Clause) | What Gets Printed |
| :--- | :--- | :--- | :--- | :--- |
| `length = 8` | Valid | `true` | `false` | Both accept |
| `length = 15` | Invalid (too long) | `false` | `true` | Both reject |
| `length = 2` | Invalid (too short) | `false` | `true` | Both reject |

### Why the Boolean Values Are Opposites

For a valid input like `8`, Approach A evaluates to `true` while Approach B evaluates to `false`:
- **Approach A tests for success:** *"Is this length valid?"* For `8`, the answer is **YES (`true`)**.
- **Approach B tests for failure:** *"Is this length broken?"* For `8`, the answer is **NO (`false`)**.

Because the two conditions ask opposing questions, their boolean results are opposite, but both produce the exact same program behavior: `8` is accepted.

### How Guard Clauses Short-Circuit Early

The `||` operator in a guard clause gives you an automatic performance and safety benefit:

```java
if (length < 3 || length > 12)
```

- When `length = 1`: Java evaluates `1 < 3`, which is `true`. Because `true || anything` is always `true`, Java **stops immediately** and enters the guard block. It never evaluates the right-hand side (`1 > 12`).
- The program exits at the first sign of an error without doing unnecessary work.

### Example 2: Event Registration with Multiple Conditions

Suppose a workshop registration requires the attendee to be at least 16 years old and to have paid the registration fee:

```java
int attendeeAge = 18;
boolean hasPaidFee = true;

// Approach A: Positive check
if (attendeeAge >= 16 && hasPaidFee) {
    System.out.println("Registration confirmed.");
} else {
    System.out.println("Registration requirements not met.");
}

// Approach B: Guard clause (inverted condition)
// Flip >= to <, flip hasPaidFee to !hasPaidFee, swap && to ||
if (attendeeAge < 16 || !hasPaidFee) {
    System.out.println("Registration requirements not met.");
    return;
}

System.out.println("Registration confirmed.");
```

**Short-circuit in action:**  
If `attendeeAge` is `14`, the check `attendeeAge < 16` is `true`. Java exits immediately without checking `!hasPaidFee`.

### Example 3: Shipping Box Dimensions with Three Conditions

A courier accepts parcels only if width, height, and length all stay within parcel limits ($width \le 100$, $height \le 100$, and $length \le 150$):

All three checks must pass:
```java
int width = 80;
int height = 60;
int length = 120;

// Approach A: Positive check
if (width <= 100 && height <= 100 && length <= 150) {
    System.out.println("Parcel dimensions accepted.");
} else {
    System.out.println("Parcel exceeds size limits.");
}
```

Applying condition inversion: flip every `<=` to `>`, and swap every `&&` to `||`:
```java
// Approach B: Guard clause
if (width > 100 || height > 100 || length > 150) {
    System.out.println("Parcel exceeds size limits.");
    return;
}
System.out.println("Parcel dimensions accepted.");
```

**Short-circuit in action:**  
If a parcel has a width of `110`, the first check `width > 100` evaluates to `true`. Java enters the error branch immediately without measuring `height` or `length`.

### The Common Inversion Mistake

When writing a guard clause, developers sometimes flip the comparison operators but forget to swap `&&` to `||`:

```java
// WRONG: A number cannot be less than 30 AND greater than 50 at the same time
if (pressurePsi < 30 && pressurePsi > 50) { ... } // Never runs
```

Always remember: if success requires ALL requirements (`&&`), failure occurs if ANY requirement fails (`||`).

### Example 2: Tiered Ranges and Top-Down Order

Categorizing network latency (ping) into performance tiers:

- Less than `20` ms: Excellent
- `20` to `60` ms: Good
- `61` to `150` ms: Fair
- Above `150` ms: Poor

```java
int pingMs = 45;

if (pingMs < 20) {
    System.out.println("Connection: Excellent");
} else if (pingMs <= 60) {
    System.out.println("Connection: Good");
} else if (pingMs <= 150) {
    System.out.println("Connection: Fair");
} else {
    System.out.println("Connection: Poor");
}
```

#### Top-Down Range Exclusion
Java evaluates `if` and `else if` statements in top-down order. Reaching `else if (pingMs <= 60)` guarantees that `pingMs < 20` evaluated to `false`. Therefore, `pingMs` is already known to be at least `20`. Writing `pingMs >= 20 && pingMs <= 60` is redundant.

#### Inclusive vs. Exclusive Boundaries
Check whether boundary thresholds include the endpoint:
- `< 60` excludes `60`.
- `<= 60` includes `60`.

## 3. Tiered Calculations (The Tiered Rate Pattern)

Progressive taxes, cloud storage, and utility bills apply in slices rather than a single flat percentage across the entire total.

### Example 1: Free Allowance with Over-Quota Charge

Suppose a cloud storage plan provides `15` GB free of charge. Any storage used beyond `15` GB costs `2` euros per gigabyte:

```java
int storageUsedGb = 22;
int fee = 0;

if (storageUsedGb <= 15) {
    fee = 0;
} else {
    // Only the excess (22 - 15 = 7 GB) is charged
    fee = (storageUsedGb - 15) * 2;
}

System.out.println("Storage fee: " + fee + " euros");
```

### Example 2: Two-Tier Stepped Calculation

A city taxi service charges:
- First 3 kilometers: Flat base fare of 5.00 euros.
- Distance beyond 3 kilometers: 1.50 euros per additional kilometer.

For a trip of 8 kilometers:
1. The first 3 km are covered by the base fare: 5.00 euros.
2. The remaining 5 km ($8 - 3$) incur the distance rate: $5 \times 1.50 = 7.50$ euros.
3. Total fare = $5.00 + 7.50 = 12.50$ euros.

```
Total Distance: 8 km
[ 0 to 3 km ] -> Flat Base Fare = 5.00
[ 3 to 8 km ] -> 5 km * 1.50   = 7.50
Total         = 12.50 euros
```

```java
int distanceKm = 8;
double totalFare = 0.0;

if (distanceKm <= 3) {
    totalFare = 5.0;
} else {
    totalFare = 5.0 + (distanceKm - 3) * 1.50;
}

System.out.println("Total fare: " + totalFare + " euros");
```

### Example 3: Multi-Tier Progressive Revenue Tax

Progressive tax systems apply higher rates only to income within specific brackets:

- Bracket 1 ($0 to $10,000): 0% tax (Tax = 0.00).
- Bracket 2 ($10,001 to $30,000): 10% tax on the amount over $10,000 (capacity: $20,000 \times 0.10 = $2,000.00).
- Bracket 3 (above $30,000): 20% tax on the amount over $30,000.

For an annual freelance revenue of $45,000:
- Bracket 1: $0.00
- Bracket 2: ($30,000 - $10,000) \times 0.10 = $2,000.00
- Bracket 3: ($45,000 - $30,000) \times 0.20 = $3,000.00
- **Total Tax:** $0 + $2,000.00 + $3,000.00 = $5,000.00

```java
int revenue = 45000;
double tax = 0.0;

if (revenue <= 10000) {
    tax = 0.0;
} else if (revenue <= 30000) {
    tax = (revenue - 10000) * 0.10;
} else {
    // 2000.0 (Bracket 2 max) + excess taxed at 20%
    tax = 2000.0 + (revenue - 30000) * 0.20;
}

System.out.println("Calculated tax: " + tax + " dollars");
```

### The Common Flat-Bracket Mistake

The **flat-bracket mistake** occurs when developers charge the entire quantity at the highest tier's rate:
```java
// WRONG: Taxing the full 45,000 at 0.20 produces 9,000 instead of 5,000
if (revenue > 30000) {
    tax = revenue * 0.20; 
}
```
In reality, only the marginal amount exceeding the threshold incurs the higher rate.

## 4. Range Overlap on a Number Line

An interval `[start, end]` contains all numbers between its start and end points inclusive. For example, `[3, 8]` contains all values from 3 through 8.

### Example 1: Point Inside a Range

Testing whether a sound frequency lies within the human audible spectrum `[20, 20000]` Hz:

```java
int frequencyHz = 440; // Concert pitch A

if (frequencyHz >= 20 && frequencyHz <= 20000) {
    System.out.println("Audible to human ears.");
} else {
    System.out.println("Inaudible frequency.");
}
```

---

### Example 2: Checking If Two Schedules Overlap

Suppose person A reserves a meeting room from `aStart` to `aEnd`, and person B requests the room from `bStart` to `bEnd`. The two reservations conflict if they share any time:

```
Schedule A: [  1  ==========  6  ]
Schedule B:             [  4  ==========  9  ]
Conflict:               [ 4 .. 6 ]
```

Instead of listing every overlapping case, check when the two bookings do **not** conflict (they are completely separated in time):
1. Schedule A ends before Schedule B starts (`aEnd < bStart`), or
2. Schedule B ends before Schedule A starts (`bEnd < aStart`).

Inverting this condition gives the conflict test:
- `aEnd < bStart` flips to `aEnd >= bStart`
- `bEnd < aStart` flips to `bEnd >= aStart`
- `||` swaps to `&&`

```java
int aStart = 9;
int aEnd = 12;
int bStart = 11;
int bEnd = 14;

boolean hasConflict = aEnd >= bStart && bEnd >= aStart;

if (hasConflict) {
    System.out.println("Room booking conflict detected.");
} else {
    System.out.println("Both reservations approved.");
}
```

### Example 3: Finding the Overlap Duration

To find the exact start and end of the conflicting window:
- The overlap starts at the later of the two starts: `Math.max(aStart, bStart)`
- The overlap ends at the earlier of the two ends: `Math.min(aEnd, bEnd)`

```java
int conflictStart = (aStart > bStart) ? aStart : bStart;
int conflictEnd = (aEnd < bEnd) ? aEnd : bEnd;

if (conflictStart <= conflictEnd) {
    int duration = conflictEnd - conflictStart;
    System.out.println("Conflict duration: " + duration + " hours");
} else {
    System.out.println("No conflict.");
}
```

## 5. The Remainder Operator (%) and Cycles

The `%` operator returns the integer remainder after division:
- `14 / 4` evaluates to `3` (integer division drops the remainder).
- `14 % 4` evaluates to `2` ($14 = 4 \times 3 + 2$; the remainder is 2).

### Example 1: Grouping Items and Divisibility

Checking whether 28 participants can be organized into equal teams of 4 with no one left over:

```java
int participants = 28;
int teamSize = 4;

if (participants % teamSize == 0) {
    System.out.println("Equal teams formed with no extra players.");
} else {
    int remaining = participants % teamSize;
    System.out.println("Players left over: " + remaining);
}
```

When checking divisibility by a variable divisor, always verify the divisor is not zero:
```java
if (teamSize == 0) {
    System.out.println("Team size must be greater than zero.");
    return;
}
```

### Example 2: The Days of the Week Wheel (7-Day Cycle)

The remainder operator wraps numbers back around repeating cycles. For instance, the 7 days of the week repeat every 7 days (0 = Sunday, 1 = Monday, ..., 6 = Saturday):

```java
int today = 2; // Tuesday
int daysAhead = 10;

int futureDay = (today + daysAhead) % 7; // evaluates to 5 (Friday)
```

To convert a total duration in hours into full days and leftover hours:
1. Integer division (`/ 24`) extracts full days.
2. Remainder (`% 24`) extracts leftover hours.

```java
int totalHours = 54;
int days = totalHours / 24;    // 2 days
int leftoverHours = totalHours % 24; // 6 hours
```

### Negative Numbers with the Remainder Operator

In Java, `%` computes the remainder rather than mathematical modulo. If the number being divided is negative, the remainder is negative:
- `-5 % 3` evaluates to `-2` (not `1`).

To wrap negative numbers cleanly in a cycle of size $N$:
```java
int wrapped = ((val % n) + n) % n;
```
